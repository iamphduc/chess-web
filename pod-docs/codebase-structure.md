# Codebase structure

A client-side chess web app: Vite + React 18 + TypeScript + Redux Toolkit, deployed to GitHub Pages under `/liem-sparring/`. No backend, no database, no auth; all state is in the browser (Redux store).

## Layout

- **`index.html` → `src/index.tsx` → `src/App.tsx`**: the root `index.html` is the Vite entry and loads `/src/index.tsx` as a module. `index.tsx` wraps the app in the Redux `Provider` and the `DndProvider` from `react-dnd-multi-backend` with its `HTML5toTouch` preset (mouse uses the HTML5 backend, the first `touchstart` switches to the touch backend), plus a touch-only drag preview that draws the dragged piece at the square size (the `PieceDragPreview` component in the board's `components` folder); `App.tsx` mounts `useHashRoute` (`src/app/`) and renders the home page (`src/features/home/`) on `#/`, else the board screen.
- **`src/app/`**: the Redux store (`store.ts`: the `board`, `view`, `match` and `review` reducers), typed hooks (`hooks.ts`) and the hash screens. `route.ts` holds `Screen` (`home`, `play`, `two-players`, `review`), `parseHash`, `hashFor`, `goTo` and the `arriveAt` thunk that brings the store in line with the screen asked for. `useHashRoute.ts`, mounted once in `App.tsx`, runs it on load and on every `hashchange`, and rewrites a hash it didn't show with `history.replaceState`.
- **`src/features/home/`**: the home page (`Home.tsx`, `main.home`): the mark, the hero, the Level and You play radio groups (`RadioGroup.tsx`: arrow keys, Home and End), Play (`playFromHome`: `startLiemGame`, then `goTo("play")`) and the Two players button (`a.button.home__two-players`). Its look is `Home.css`.
- **`src/features/board/`**: the UI and Redux state for the game.
  - `Board.tsx` and `components/*` (`TopBar`, `Square`, `Piece`, `Promotion`, `Notation`, `GameOver`, `Player`, `BoardSidebar`, `Button`, `ResignButton`, …): presentation; drag-and-drop via `react-dnd`, animation via `framer-motion`. `topBar.ts` is the pure top-bar title (`topBarTitle`), `material.ts` the pure "+N" line (`materialLine`: the captured pieces and the lead, promotions counted), `boardSize.ts` the square size (`squareSizeFor`: 39, 52 or 78 px), `resignConfirm.ts` the pure Resign-then-Confirm press rule (3000 ms, time passed in), `gameEnd.ts` the result (`gameEnd`, `canResign`), `gameOverView.ts` the game-over card's text and when it shows, `gameOverEntrance.ts` the card's entrance (its timings, and `animate` or `instant`), and `pieceMotion.ts` how pieces move (`GAME_MOVE_TRANSITION`, a 200 ms ease-in-out tween for every game-board move; `REVIEW_STEP_TRANSITION`, the review's 150 ms ease-out one-ply step; `reviewStepMotion`, slide or snap on the review board).
  - `src/features/board/BoardSlice.ts`: the Redux reducer. It keeps one engine `GameState` per ply (`engineHistory`), asks the engine for legal moves and applies moves through it, and keeps the UI-only parts itself: notation, last-move highlight, the promotion picker step. It keeps no list of taken pieces: the cards' captured glyphs and "+N" come from `materialLine` on the current position. The picker's choices, `PiecePromoted`, live in `piecePromoted.ts`, not in `components/Promotion.tsx`, so the reducer and `engineAdapter.ts` never import the picker component (which imports the reducer).
  - `src/features/board/engineAdapter.ts`: the bridge between the pure engine and the UI. It turns a `GameState` into the `HistorySquares` grid the UI reads, builds engine `Move`s from UI actions, maps the picker choice to a promotion kind, and reports the checked king and game-over state.
  - `orientation.ts`: pure board-to-screen math for the flip. Board coordinates stay White's view everywhere (`y = 0` is rank 8, `x = 0` is the a-file); `toDisplay`, `displayOrder`, `squareLabels` and `promotionPlacement` map them to where a square renders, which squares carry the rank and file labels, and where the promotion picker sits.
  - `viewSlice.ts`: the `view` reducer, `{ flipped, soundOn }`. `toggleFlip()` turns the board around; it isn't saved. `toggleSound()` turns move sounds on or off; the Sound button saves it, and the slice loads it at start. The board `reset` touches neither. `Board.tsx` renders squares in `displayOrder(flipped)` with each square keyed by its board index, swaps the player cards (keyed by color, so each clock stays with its player), and wraps the board in framer-motion `MotionConfig reducedMotion="user"`. The Flip button blocks the layout animation for the flip render, so pieces jump instead of sliding.
  - **Move sounds:** `src/features/board/sound.ts` holds the `SoundKind`s, the `SOUND_FILES` map, `pickSound` (game end > check > promotion > castle > capture > move) and `soundToPlay` (play a stored sound only when it's a new object and sound is on). `BoardSlice` stores `moveSound: { kind } | null`, a new object per completed ply (a promotion completes on the pick). `src/features/board/soundSetting.ts` loads and saves the setting in `localStorage` under `liem-sparring.sound` (`"on"`/`"off"`, default on, storage errors ignored; when that key is unset it reads the pre-rename key `chess-web.sound`). `src/features/board/soundPlayer.ts` is the Web Audio player: `install` fetches the files and waits for the first user gesture to make and resume the `AudioContext`; `play` starts a decoded buffer through one gain node and sets `data-last-sound="<kind> <n>"` on `<html>`. Its browser parts are injected, so the tests use fakes. `src/features/board/useMoveSound.ts`, mounted once in `Board.tsx`, installs the app's single player and plays each new `moveSound`.
  - `squareMarks.ts`: pure choice of the marks a square shows (highlight tint, dot or ring hint, check glow, drop edge); `Square` only renders what it returns. Mark colors come from the `--board-*` tokens in `src/index.css`.
  - `src/features/board/clock.ts`: pure clock math in whole milliseconds (drift-free countdown from `Date.now()` passed in, `MM:SS` / tenths format, low-time stages, the hand's quarter-turn angle, phase and tick interval, the 10s alert text). No React, no timers.
  - `src/features/board/components/Player.tsx` keeps each player's `ClockState` and one timer per turn (keyed on `tickInterval`, each tick timed to land when the digits change), and dispatches `stop()` on flag fall or game over. `PlayerClock.tsx` is the presentational pill: `role="timer"`, inline SVG clock face whose hand jumps 90° per second, digits, and a hidden `role="alert"` sibling at 10s.
  - `src/features/board/components/avatar.ts`: `avatarSrc(name)` maps a player's avatar file name to its imported image URL through a static map, and returns `null` for any other name; the card then shows a square disc with its color's king (♔ or ♚). Only his photo has an image now. Add a line there when a player entry (`player.json`, via `LIEM.entry`) uses a new avatar.
- **`src/features/liem/`**: vs Liem, the ladder: six sparring bots named Easy, Medium, Hard, Harder, Expert and Master (strength steps 1400 to 2500; the numbers stay in code), and Le Quang Liem himself at the last step, all playing his book, then Stockfish. `matchSlice.ts` (store key `match`: mode, which starts as `"liem"` with `setupOpen` true, the home state, and isn't saved; color pick, strength, his last choice, his status), `levelView.ts` (`LEVEL_NAMES`, the one place to rename a level, and every text a level shows: the card's name, detail and phone detail, home's step name, ★ and rating (`null` for sparring, "GM · 2732" at Liem), the step label and engine line, the out-of-book text; components add no words of their own), `liemActions.ts` (`switchMode`, `startLiemGame`, `goHome`, `replayLiemGame`), `components/Star.tsx` (the ochre ★ SVG), `liemTurn.ts` (whether it's his turn), `opponentController.ts` (loads him once, drops stale answers, retries), `bookNote.ts` (the note and badge view), and `liemOpponent.ts` (loads both books and the Stockfish worker). `useLiemOpponent.ts`, mounted once in `Board.tsx`, makes one controller per mount (disposed on unmount, so StrictMode's second mount gets a fresh one), preloads him once a vs-Liem game starts, asks him on each of his turns and cancels otherwise, and plays his answer with `playOpponentMove` then `opponentMoved`. It imports `liemOpponent.ts` with a dynamic `import()`, so Stockfish and the books stay out of the entry bundle (`tests/build.test.ts › engine and books load lazily`).
  - **Layout (`Board.tsx`):** the board screen, on `#/play`, `#/two-players` and `#/review`. There are no mode tabs and no setup card: home picks the mode, level and color. `header.top-bar` (56 px, `TopBar`) holds ← Home (`a[href="#/"]`), the title from `topBarTitle`, and nothing else (it takes no props; the review's Play again is in its Moves card foot). Below 768 px its gap and button sides are 8 px and the title is 14 px, so "Review · vs Medium" fits whole at 375 px. The board column (`.board`, 8 squares wide) holds a player card, `.squares` and a player card. The sidebar holds the book note (vs Liem only), then the Moves card (`.card.moves-card`: the scoresheet `Notation` list and a foot). **Player cards:** a card with no photo shows a 40 px disc (`span.player__disc`, `aria-hidden`, `--surface-2` fill, ink glyph); every disc and Liem's photo (`.player__avatar`) is a square with the 4 px `--radius` corner: ♔ for White, ♚ for Black, his ♞ for a sparring bot (plus `.liem-sparring-avatar`). Every `.board > .player` is 60 px tall (8 px above and below the 44 px text column), with 12 px from the avatar to the name and 16 px from the name side to the clock, and `.player__time` has a fixed width with tabular figures, so the clock box never shifts. **Two players:** the "White" and "Black" cards (`src/game/players.ts`), each with its disc and no photo or GM tag, and a foot of Play, New game (the old Reset), Flip and Sound before Play; New game, Resign, Flip and Sound while the clocks run; New game, Flip and Sound once the game is over. **vs Liem:** his card (his name, title and avatar from `LIEM.entry`, with `LiemCardDetail`) on his color's side and the "You" card (your color's disc) on yours, following the flip; a foot of New game (`replayLiemGame`: same level and color), Resign, Flip and Sound in a game, and Review game (`a[href="#/review"]`, only once the game can be reviewed), New game, Flip and Sound after it. **Resign** (`ResignButton`, `button.resign-button`, 104 px) shows while `canResign` holds; from 992 px every foot is one row. From Easy to Master his card is the sparring bot's: the ♞ disc and the level's name, no GM tag or star. At the Liem step it's his photo, GM tag and "Le Quang Liem" (no star on the in-game card; the ochre ★ is on home's "★ Liem" step). Under the name there's only "★ Book · N" (`[data-book-games]`) while he's in his book, "Thinking…" while he loads or thinks, and otherwise nothing: no "Plays Liem's openings", no rating and no Stockfish pill (`[data-engine]`). Each card shows `.player__material` once that side has captured something or is ahead: its own line under the name, 4 px below it, with the captured pieces (`.player__captured`) first and then "+N" (`.player__advantage`, only when ahead). On his card "★ Book · N" or "Thinking…" shares that line, after the material, at the line's end. The glyphs cut first (ellipsis); "+N" and his detail never do. `Player.css` holds every `.board > .player` at 60 px. **Pieces** (`Piece.tsx`) slide with `GAME_MOVE_TRANSITION`, 200 ms ease-in-out (click, tap, his move, castling's rook, en passant; when his reply lands mid-move the piece still ends on the store's square); the Flip and a drag drop land at once (`useInstantLayoutTransition`, so castling's rook jumps on a drop too); with `prefers-reduced-motion` every piece jumps (`MotionConfig reducedMotion="user"`). The game-over card (`.game-over`) has `data-entrance="animate"` (a 300 ms pause, then the scrim fades in over 200 ms and the card rises 8 px over 250 ms) or `"instant"` (reduced motion, or a later mount for the same ended game). Below 768 px the badge drops its count ("★ Book"); screen readers still get the whole line. The book note (`[data-book-state]`) is `waiting`, `in-book` or `failed` (with Try again); out of his book it shows no note, and below 992 px an empty slot keeps its height until a new game so the page doesn't scroll, and a new game brings back `waiting`. From 992 px up the board column and a 380 px sidebar sit side by side with a 24 px gap; below that they stack, board first.
- **`src/features/review/`**: the post-game review of a vs-Liem game (plan `post-game-review`). `reviewSlice.ts` (store key `review`: open, the game it belongs to, status, one eval per position, the cursor, key-moment statuses, the phone sheet; `reset` and `newGame` clear it), `reviewLayout.ts` (`graphPlacement`, where the graph shows; `playAgain`), `reviewActions.ts` (when **Review game** works: a finished vs-Liem game with a move of yours and no promotion to pick; closing the review (`backToGame`); where the pass starts; trying a move at a key moment; arrow keys; the guarded `buildReview`), `reviewLimits.ts` (`REVIEW_LIMITS`, see `pod-docs/decisions.md`), `keyMomentView.ts` (the card's state), `tryBoard.ts` (click-to-try rules) and `graphGeometry.ts`. `useGameReview.ts`, mounted once in `Board.tsx`, runs the analysis pass on his engine through `useLiemOpponent`'s `analyse` while the review is open and analysing (stopped on close or a new game), loads his books once with a dynamic `import()`, builds the model and handles tried moves and the arrow keys. `components/` holds the prop-driven `ReviewGraph` (the summary card: the graph and the accuracy line), `ReviewBoard`, `KeyMomentCard`, `BottomSheet`, `MoveList`, `LeftBookNote` (the list's first line) and `StepButtons`; `moveNumber.ts` holds `moveNumber` (the move number of a ply), shared by `MoveList` and `LeftBookNote` so neither imports the other; their look is `src/styles/review.css` and each component's own CSS file, with the `--grade-*` and `--review-scrim` tokens.
  - **Layout (`Board.tsx`):** on `#/review` the top bar holds only ← Home and the title ("Review · vs Medium"). `.board-screen.review` holds the board column (the `ReviewBoard` in `.squares` with the player cards around it and the step buttons under it) and the sidebar, three cards (sprint polish): the key-moment card; the summary (`section.card[data-review-graph]`: the 80 px win % graph of your side, no side switch, then `.review-summary__accuracy`: `.review-accuracy` "40 %" or "—", "accuracy", and `[data-count]` "?! N", "? N" and "?? N" in grade colors); and the Moves card (the scoresheet `MoveList`, whose first line is `[data-left-book]` "Left his book at move N · he played X in G games", "Left his book at move N" or "Stayed in his book the whole game", none without his books; and a foot of Play again (`button.button.button--play`, `playAgain`: a new game at the same level and color, then `#/play`), Flip and Sound; the review has no `a[href="#/play"]`, and the browser's Back still goes to `#/play`). The `ReviewBoard` draws its pieces as motion elements keyed by piece, with layout ids `review-<gameId>-<piece>` (never the game board's): a one-ply step (◀, ▶, an arrow key, an adjacent move in the list) slides with `REVIEW_STEP_TRANSITION` (150 ms ease-out, not the game board's 200 ms ease-in-out), and opening the review, a jump of 2 or more plies, a flip, a resize or another game snaps (`reviewStepMotion`). Below 768 px the key-moment card and then the summary are in the bottom sheet while it's open and up. `graphPlacement` puts the graph in exactly one place: the sheet, or the top of the sidebar when the sheet is closed or sits low (no scrim) while you try a move.
- **`src/game/engine/`**: the pure rules engine, the only one the app uses. Immutable `GameState` (`game-state.ts`), the `Move` and `Position` types (`move.ts`; `engine.ts` re-exports them, so `from ".../engine/engine"` still works, while `moves/*` import them from `move.ts` so they never import the engine that imports them), `legalMoves`/`applyMove` (`engine.ts`), per-piece move generators and shared geometry (`moves/`), attack map and check (`moves/attack.ts`), checkmate/stalemate (`game-status.ts`), promotion ids (`moves/promotion.ts`). Fully unit-tested, including perft counts and a replayed recorded game.
  - `PROMOTED_IDS` in `src/game/engine/moves/promotion.ts` is the single table of promoted-piece ids (`*Promoted1..4`, at most 4 per type). `src/constants.ts` re-exports it as `PromotionBoard` for the picker.
- **`src/game/opponent/`**: the computer opponent that plays like a real player (sprint `liem-book` of plan `play-like-liem`). Pure TypeScript, no React.
  - `position.ts`: the codec between engine `GameState`/`Move` and text. `squareName` (`[7,4]` is `e1`), `moveToUci`, `uciToMove` (returns the matching move from `legalMoves`, or `null` for anything not legal, including a missing or extra promotion suffix), `positionKey` (FEN fields 1 to 4; the en-passant square is written only when the side to move has a legal en-passant capture, so transpositions share a key) and `toFen` (the key plus counters, default `0 1`).
  - `types.ts`: the book format (`Book`, `BookMove` tuple `[uci, win, draw, loss, otb, lichess, chesscom]`, `BookName`, `GameSource`), the `PlayerEntry` type, and the `moveGames`/`positionGames` count helpers.
  - `engine/`: the Stockfish boundary, `MoveEngine` and `EngineError` (`move-engine.ts`), the UCI protocol (`uci-engine.ts`) and the Web Worker glue (`stockfish-worker.ts`). `analyse(fen, limits)` runs one MultiPV search (`go depth D movetime T`, `MultiPV` lines) and returns the scored top lines (`EngineLine`, `lines.ts`) plus `bestmove`. The app never sends `UCI_LimitStrength` or `UCI_Elo`.
  - `book.ts`: picks the book for the game clock (`bookForClock`), looks a position up with the thin-line fallback (`lookupBook`) and makes the weighted pick.
  - `opponent.ts`: `createOpponent`, which chooses a move from the book, else from the engine's lines, and returns only moves in `legalMoves`. `strength.ts` holds the strength steps; `step-profiles.ts` holds `STEP_PROFILES`, each step's search limits and pick rules, including each sparring level's `mistakeChance`, `blunderChance`, `blunderMaxCp` and `hangWeight` (all required; Liem's are 0). The values come from `npm run calibrate` and its measure mode, see `## Calibrating the strength steps`; going up the steps, depth never falls and the loss limits, chances, `blunderMaxCp` and `hangWeight` never rise. A search stops at whichever comes first, its depth or its `movetimeMs`. Full's real limit is time: at 1000 ms it stops at depth 13 to 16 and never reaches its depth 18, yet it still plays Stockfish's best move. The 1 s limit stays so phones answer quickly.
  - `human-move.ts`: `chooseHumanMove`, the pick a human of the step's strength would make among the engine's lines: play a seen mate within `forceMateIn`, avoid walking into a mate, drop lines other than the best that hang material (`material.ts`, `hangsMaterial`), never skip a capture that nets 3 or more (`materialNet`) for a line that wins less unless the engine rates that line better, then pick within `maxLoss` win % points by `exp(-loss / temperature)`, with a rare slip (`slipChance`) up to `slipMaxLoss`, and a tighter `aheadMaxLoss` when well ahead. A line 300 cp or more below the best (`MAX_DROP_CP`) is outside every limit, because win % flattens when one side is far ahead and a lost piece costs only a few points. Before those picks, a sparring level that is not well ahead (top line under `AHEAD_WIN`, 85 %) draws once: under `blunderChance` it picks from the **blunder band** (loss ≥ 30 win %, and under `blunderMaxCp` cp when both scores are cp), under `blunderChance + mistakeChance` from the **mistake band** (20 to under 30, and under `MAX_DROP_CP`). Band lines are weighted `exp(-(loss - least) / 10)`, times `hangWeight` for a line that hangs material; an empty band falls back to the normal pick. Liem's chances are 0, so he never draws.
  - `players/`: one folder per player (`player.json` and the two committed book JSON files), plus `index.ts` exporting `PLAYERS` and `LIEM`. Nothing outside this folder hard-codes a player's data.
  - **Relative imports only** under `src/game/opponent/` (no `game/` aliases), so the Node import script under `scripts/` (run with `tsx`) and its tests can load it.
  - **No PGN parser in the app:** `chess.js` (or any PGN parser) is imported only under `scripts/`, never under `src/`. Raw PGN stays in the git-ignored `/games/` folder.
- **`src/game/review/`**: the review model, pure TypeScript with relative imports. `moves.ts` (each ply's UCI move and its `13.Nd5` / `13...Nc6` label), `grade.ts` (win %, drop, accuracy, the 10/20/30 grades, the mate rules and the found rule; `gradeMove` takes optional levels, such as `LICHESS_LEVELS` 5/10/15, and is the only place a move is graded), `game-accuracy.ts` (Lichess's game accuracy: its win % from a fixed +15 cp start, per-move accuracy with the +1 bonus, volatility weights and the weighted plus harmonic mean), `build-review.ts` (`buildReview`: graded moves, game accuracy, his book plies, where the game left his book and the 3 key moments) and `analysis-runner.ts` (one search at a time over the game, with tried-move checks jumping the queue).
- **`scripts/book/`**: the Node import script that builds the books (run with `tsx`, never bundled). `timecontrol.ts` (clock estimate and slow/online class), `games.ts` (PGN to his filtered, deduped, colored games, parsed with `chess.js` and replayed through `uciToMove`), `build-book.ts` (games to the two `Book`s, the `minGames` floor and the 3 MB budget, byte-stable JSON), `sources.ts` (Lichess account, Lichess export, Chess.com monthly archives, retries on 429, all through an injected `fetch`), and `import-book.ts` (`runImport` plus the thin CLI). Tests in `scripts/book/__tests__/` use fixture PGN and HTML only.
- **`scripts/calibrate/`**: the dev-only calibration script (run with `tsx`, never bundled, never in tests or CI). `match.ts` (openings, one game, a pairing's tally and Elo gap, all with injected players), `anchor.ts` (Stockfish at a set `UCI_Elo` through its own small UCI player, and the Node glue that runs one Stockfish per child process), and `calibrate.ts` (flags, the game pool, the per-step tables). Tests in `scripts/calibrate/__tests__/` use fake players and a fake UCI pipe only.
- **`scripts/ladder/`**: the dev-only human baselines for the sparring ladder (run with `tsx`, never bundled, never in tests or CI). `rates.ts` (`measureGames`: per-40-move inaccuracies, mistakes and blunders at the review's 10/20/30 and Lichess's 5/10/15, hung pieces, missed captures, average win % loss and accuracy, all graded through `gradeMove`; plus `targetFor` and `withinTarget`, the 75 % target and its 25 % tolerance), `lichess.ts` (the polite Lichess client, the arena and game endpoints, Lichess evals to side-to-move evals, the rating band) and `baseline.ts` (flags, collecting players and games, the file and its summary). `human-baselines.json` is the committed output. Tests in `scripts/ladder/__tests__/` use inline fixtures and a fake `fetch` only. See `## Human baselines`.
- **`src/game/pieces/*`**: presentation only. Each piece class holds its image, weight and notation letter; no move rules and no game state. `src/game/piece-factory.ts` maps a `PieceType` to its piece object, and `src/game/piece-notation.ts` writes move notation.
- **`src/game/board-types.ts`**: the UI board types, `Square` (`{ pieceType, isEnemyAttacked }`) and `HistorySquares`.
- **`src/game/piece-type.ts`**: the `PieceType` enum, including the promoted ids. `src/game/players.ts` holds the two players' names and avatars.
- **`src/constants.ts`**: `PromotionBoard`, square sizes and the default clock time. It is imported by relative path; `constants` is not a bare-import prefix.
- **`src/assets/`**: piece SVGs, his photo `le-quang-liem.png` and the self-hosted Quicksand fonts (`fonts/`).

## Stack & conventions

- **Toolchain:** Vite 8 (`vite.config.ts`) with `@vitejs/plugin-react` 6, Vitest 5, TypeScript 5.x (below 6). Node 22.12 or newer (Vitest 5 needs it); local is Node 24. React 18, Redux Toolkit 1.x, react-dnd 16 (with `react-dnd-multi-backend` 9 for touch) and framer-motion 7.
- **Scripts:** `dev` = `vite`, `build` = `tsc --noEmit && vite build` (Vite only transpiles; `tsc` type-checks `src/` only, not `vite.config.ts` or `tests/`), `preview` = `vite preview`, `test` = `vitest run`. Build output goes to `dist/`.
- **Base path:** `base` is `/liem-sparring/` in dev, build and preview. Files in `public/` are referenced as `/x`, never `%PUBLIC_URL%`.
- **Bare imports:** `app/`, `assets/`, `features/`, `game/` and `hooks/` resolve to `src/<prefix>/`. The single source is tsconfig `paths` (no `baseUrl`); Vite reads it through `resolve.tsconfigPaths`. Anything else, such as `constants`, is imported by relative path.
- **Sounds:** move sounds live in `public/sounds/` (one `.wav` per kind, each under 100 KB), with their source and CC0 licence in `public/sounds/CREDITS.md`. Vite copies them to `dist/sounds/`; the player loads them from `${import.meta.env.BASE_URL}sounds/`.
- **The Look (tokens):** every color, size and space comes from the tokens in `src/index.css` `:root` (plan `ui-refresh`, `## Look`): the palette (`--bg`, `--surface`, `--surface-2`, `--line`, `--ink`, `--soft`, `--accent`, `--gold`, `--go`, `--go-ink`), space `--space-1` to `--space-6` (4 to 32 px), `--radius`, type `--text-hero`, `--text-title`, `--text-body` and `--text-small` (30, 20, 16 and 14 px; nothing smaller) and `--font`, then the `--board-*`, `--clock-*` and `--grade-*` sets, `--review-scrim` and `--game-over-scrim` (the `--ink` value at 40 %, behind the game-over card). Body text is Quicksand 600 (`body { font-weight: 600 }`); headings, buttons, names, clocks and other bold text are 700, and no CSS sets another weight (`tests/theme.test.ts › body text is 600 and bold stays 700`). No CSS file outside `index.css` names a hex, `rgb()` or `hsl()` color or a gradient. `--gold` (ochre) is never a text color, only bars, borders and the ★. Light only, no dark mode. `tests/look-helpers.ts` holds the checks (`lookViolations`, `contrast`); `tests/leftover-styles.test.ts` guards all of `src/` (no old token, every `var(--x)` declared, every stylesheet clean).
- **Base classes:** `src/styles/look.css` holds `.card` (16 px padding, 1 px `--line` border, 4 px radius), `.card--flush`, `.card__head`, `.card__foot`, `.stack`, the `.scoresheet` move list (the signature detail: alternate `--surface-2` rows, the current move in an ink chip, marks in red ink) and the 3 px ink focus ring. `src/features/board/components/Button.css` holds `.button` (secondary), `.button--play`, `.button--icon` and `.button--sound-on`; an `<a class="button">` looks the same. Components use these and keep only their own layout in their CSS file.

## Building the books

`npm run book:import` rebuilds `src/game/opponent/players/le-quang-liem/book-slow.json` and `book-online.json`. It runs by hand, never in CI or tests, and **it calls the live Lichess and Chess.com APIs**. Commit the two JSON files it writes.

- **Flags:** `npm run book:import -- --lichess-user <name>` sets the Lichess account. Without it the script uses `sources.lichessUser` in `player.json`, else the account linked from the Lichess FIDE page (`sources.lichessFideUrl`). If none resolves, it warns and builds without Lichess.
- **`games/` (git-ignored):** put his over-the-board PGN files in `games/otb/*.pgn` (for example from TWIC). Downloads are saved in `games/cache/`; finished Chess.com months are read from there on the next run, and the archive list, the current month and the Lichess export are always fetched again.
- **Output:** the script prints the Lichess account used, games read and kept per source, the skipped counts by reason, the games cut short at a rejected move, and per book the games, positions, `minGames` and size. If any source fails (an HTTP error, or still 429 after 3 retries one minute apart), it exits non-zero and writes no book.
- Every request sends `User-Agent: liem-sparring-book-import/1.0 (+https://github.com/iamphduc/liem-sparring)`. The rules for which games go into which book are in `pod-docs/decisions.md` (2026-10-09 entries).

## Calibrating the strength steps

`npm run calibrate` plays each strength step against Stockfish anchors and prints a table per step. It runs by hand, never in CI or tests, and it calls nothing on the network. Run it from a clean checkout, so the table it measures is the committed one.

- **What plays:** each step moves like `createOpponent` with empty books, the lite single-thread Stockfish build (the one the browser uses), `STEP_PROFILES[step]` and a seeded random. Its rivals are **anchors**, Stockfish with `UCI_LimitStrength` at a set `UCI_Elo` (1000 ms a move), and the next step up. Each engine runs in its own Node child process, because the npm loader can't hold two in one process.
- **Games:** from a fixed list of 8 short, balanced openings, each played once with each color. A game ends on checkmate or stalemate (our rules engine), or as a draw at 200 plies (no repetition or fifty-move rule). An error ends that game; it is listed, not scored.
- **Flags:** `--steps 1400,1700,...,full` (default all), `--anchors -200,0,200` (offsets from each step's Elo, Full's is his rating; clamped to Stockfish's 1320 to 3190; `none` keeps only the next-step pairing), `--anchor-elos 2400,3190` (the same anchors for every step, in place of the offsets), `--games N` (even, default 4), `--seed N` (default 1), `--jobs N` (games at once, default up to 6).
- **Output:** a progress line per game, then per step and rival: W/D/L, errors, score %, the Elo gap estimate `-400·log10(1/s − 1)` (with `s` clamped to `[0.5/n, 1 − 0.5/n]`), the Elo that implies against an anchor, the average and largest loss per move (win % points against the move's own search, from `MoveChoice.lines`), the slip rate (moves losing more than `maxLoss`), and average and max ms per move. Max ms includes the first move's engine start-up.
- **Time:** `--games 4` over all steps is 108 games, about 20 minutes at 6 jobs. Run it in the background with output to a log file.
- **Measure mode:** `npm run calibrate -- --measure [--steps 1400,...,2500,full] [--games N] [--seed N] [--jobs N]`. Each step plays itself from his book (the 10-minute book), one side resigns after 3 engine moves in a row at -1000 cp or worse, and a game is drawn at 200 plies. Every position is graded at the review's limits (depth 18 or 500 ms), and only engine plies count. Defaults: the six sparring steps, 20 games, seed 1. It prints, per step, the profile, games, graded moves and ms per engine move, then each rate per 40 moves (review and Lichess inaccuracies, mistakes and blunders, hung pieces, missed captures, average loss, and Lichess game accuracy per side from `src/game/review/game-accuracy.ts`, loaded by `scripts/calibrate/accuracy.ts`, with no target since higher is better) as bot, human (from `scripts/ladder/human-baselines.json`), target (75 % of human) and `ok` (`yes` within 25 % of the target, for `review.mistake` and `review.blunder` only), then the three biggest drops with their FEN. Time at `--jobs 10` on 12 cores: 40 games of all six sparring steps about 30 minutes, with `full` added about 43 minutes. Run it in the background with a log, never in CI or tests. 40 games is still noisy (a rate moves about ±10 % between runs of the same table).
- Record each run that changes `STEP_PROFILES` (flags, results, the values chosen) in `pod-docs/decisions.md`. Four games per pairing is noisy: one game is ±12.5 %; read the trend across anchors, not one cell.

## Human baselines

`npm run baseline` measures how often real Lichess players near each sparring level (1400, 1700, 1900, 2100, 2300, 2500) make mistakes, and writes `scripts/ladder/human-baselines.json`. It runs by hand, never in CI or tests, and **it calls the public Lichess API** with no token or cookie. Commit the file it writes; `npm run calibrate -- --measure` compares the bots with it.

- **What it reads:** the players of recent finished standard blitz and rapid arenas (`/api/tournament`, then each arena's results), then, per level, the rated, analysed blitz and rapid games of the players within ±150 of it (closest first, 30 games a request, at most `--per-user` games a player). When the arenas run short (they rarely hold players rated 2300 and up), the opponents met in those games who are near the level are read next.
- **Which games count:** both players within ±100 of the level, edges included. Fewer than 30 widens it to ±150; fewer than 30 even then marks the level `lowSample`. Rapid games come first, then blitz up to `--games`. A game with an eval missing before its last ply is dropped and counted in `droppedGames`; a missing last eval in a live position leaves that ply out. A level with no games is left out of the file.
- **Grading:** each kept game is replayed on our rules engine and graded from ply `--skip-plies` with the review's `gradeMove`, both sides. Lichess's eval after each ply (White's view) becomes the side-to-move eval before the next ply; before ply 0 it uses +15 cp. `rates.accuracy` is the mean of Lichess's own per-player accuracy.
- **Flags:** `--games N` (kept per level, default 150), `--skip-plies N` (default 10), `--levels 1400,2500` (default all six; a partial run merges into `human-baselines.json`, keeping the other levels), `--max-users N` (players read per level, default 60), `--per-user N` (default 8), `--max-arenas N` (default 25).
- **Politeness:** one request at a time, at least 1.5 s after the last one ended; a 429 waits (its `Retry-After`, else 60 s) and retries up to 3 times, through `fetchText` in `scripts/book/sources.ts`. Requests send only `Accept` and `User-Agent: liem-sparring-baseline/1.0`. A request that hangs 3 minutes fails, and that player is skipped.
- **Cache:** raw downloads go to the git-ignored `games/baseline-cache/` and are read back on the next run, the arena list included. Delete the folder for fresh data.
- **Output:** a progress line per player read, then one summary line per level (games, band, speeds, dropped, graded moves, the per-40 rates at both level sets, hung pieces, missed captures, average loss and accuracy). A level the file kept from an earlier run (outside `--levels`, or in `--levels` but the run kept no games for it) ends with ` (kept from the saved file)`; a level this run wrote has no mark, so a full run marks nothing. A level with no entry reads `<level>: no baseline`. The file holds no usernames, game ids, game dates or moves.
- **Time:** the first run (2026-10-18, defaults) read 188 players in about 15 minutes, most of it waiting on Lichess to stream analysed games; a rerun from the cache takes seconds. Run it in the background with output to a log file.
