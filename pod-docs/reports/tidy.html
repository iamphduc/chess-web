Key decisions

Only the merge target has its own decisions.md entry. The other decisions live in the plan's Key decisions or the sprint's Shared contract. No design draft was made, since nothing changes on screen.

One sprint, code only

Why
Each item is small alone, but they piled up in the queue.
Alternatives
Fold each nit into a later feature plan, as the June entries suggested.
Consequence
One wave of three parallel slices. Seven items needing a human call stayed queued.
Who
human "go", 2026-10-21 · plan

Merge into tidy-staging

Why
The rule "each plan gets its own staging branch".
Alternatives
A shared pod-staging, which the human turned down earlier.
Consequence
Cut from main at f5d8e13. The human merges it into main.
Who
human · decisions.md → 2026-10-21 — merge target: tidy-staging

The cycle test covers all of src

Why
So any new loop fails CI, not just the three known ones.
Alternatives
Test only the three files, like no-gameover-cycle.test.ts does for one loop.
Consequence
The walk reads more than 100 files. The reviewer counted 219 files and 730 edges.
Who
agent default · plan

Type-only imports aren't edges

Why
TypeScript erases them, so they don't set load order. tsconfig.json has isolatedModules and no verbatimModuleSyntax, so an all-type brace list is erased too.
Alternatives
Count them, which the plan required unless the engineer showed they're erased.
Consequence
A plain import { Move } still counts, even for a type. Hence engine/move.ts.
Who
agent · sprint contract. The reviewer checked this rule and dismissed the concern.

Break loops by moving declarations out

Why
It's the same fix gameOverType.ts used for GameOverType.
Alternatives
Switch to import type where possible. That doesn't work for the PiecePromoted enum, which is a runtime value.
Consequence
Three small new modules. engine.ts re-exports Move and Position, so other imports stay as they were.
Who
agent · sprint contract

PositionEval lives in game/review/types.ts

Why
The pure game layer owns the type, and the features import it from there.
Alternatives
Keep it in reviewSlice.ts and import it into the game layer, which reverses the layering.
Consequence
A test checks that it's declared once.
Who
agent default · plan

Drop the kind guard from pawn.ts

Why
Moves are dispatched by kind, and the queue entry called the guard defensive only.
Alternatives
Add the same guard to knight.ts and king.ts.
Consequence
The three generators now match. Perft counts are unchanged.
Who
agent default · plan

Remove fallenPieces with no migration

Why
Nothing saves the board store, so a reload already loses it.
Alternatives
Keep reading old saved data without it. The plan listed this as the fallback if something did save it.
Consequence
Piece.getWeight() lost its last caller (queued).
Who
agent · sprint contract

saveBaseline takes read and write functions

Why
The bug fixed in PR #94 lived in main's untested write step. Passing read and write in lets a test use a fake file.
Alternatives
Test main against the real file system.
Consequence
A full six-level run never reads the saved file. A write that fails makes saveBaseline fail.
Who
reviewer's queue entry, shape set in the sprint contract
