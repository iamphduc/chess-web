1. At a glance

Goal: replace Create React App (react-scripts, no longer maintained) with Vite, and build, test and deploy from GitHub Actions instead of a local gh-pages script. The app must look and play exactly as before. This is item 1 on docs/roadmap.md, and it has to land before PartyKit online play.

What shipped:

  • Vite 8.3.2, @vitejs/plugin-react 6.1.1, Vitest 5.0.3 and TypeScript 5.9.3, all from one vite.config.ts.
  • Plain npm install works. --legacy-peer-deps is gone.
  • One workflow, .github/workflows/pod-ci.yml: verify and secrets run on every PR, and deploy publishes to GitHub Pages on push to main.
  • CRA files and packages and the gh-pages script are removed. Docs are updated.

3. Key decisions

Most choices come from docs/research/cra-to-vite.md and the plan's Key decisions. "Agent default" means the planner proposed it and it was not changed in the plan interview. Two decision entries were written: decisions.md → "Vite + Vitest replace CRA" and "GitHub Actions deploys to GitHub Pages" (both 2026-10-04). There are no design drafts.

Deploy with GitHub Actions and the official Pages actions

human
Why
Checks on every PR; deploy only from main, only when green.
Instead of
Pushing built files to a gh-pages branch from a laptop.
So
A human must set Pages Source to "GitHub Actions" before the first deploy.

Upgrade only what the move needs

human
Why
Keep the change small and the app identical.
Instead of
Also moving to React 19, Redux Toolkit 2, newer react-dnd and motion.
So
React 18, RTK 1.x, react-dnd 16 and framer-motion 7 stay.

Vite 8 + plugin-react 6 + Vitest 5 on Node 24

agent default
Why
plugin-react 6 needs Vite 8; Vitest 5 needs Node 22.12+; Node 24 matches the local machine.
Instead of
Older Vite/Vitest pairs that still accept Node 20.
So
CI pins Node 24. There is no engines field yet (queued).

@types/node → ^24

agent default
Why
Matches Vitest 5's peer range and ends --legacy-peer-deps. Research marked it untested.
Instead of
Keeping the flag or an .npmrc.
So
Proven: clean install, npm ls --all exits 0.

Explicit tsconfig paths, no baseUrl

agent default
Why
No import line changes; Vite reads it with built-in resolve.tsconfigPaths; TS 6 deprecates baseUrl.
Instead of
vite-tsconfig-paths plugin, or a hand-written resolve.alias.
So
One source for tsc, dev, build and Vitest. The TS 6 upgrade is unblocked.

base: '/chess-web/', output to dist/

agent default
Why
The documented setup for a GitHub Pages project site with no custom domain.
Instead of
CRA's relative homepage: "." and build/.
So
Dev and preview also serve under /chess-web/, so base-path bugs show up locally.

Type-check outside Vite

agent default
Why
Vite only transpiles.
Instead of
A type-check plugin.
So
build = tsc --noEmit && vite build; CI's one step covers typecheck, build and tests.

Vite's default browser target

agent default
Why
Vite does not read browserslist.
Instead of
@vitejs/plugin-legacy.
So
Chrome/Edge 111+, Firefox 114+, Safari 16.4+.

Static avatar map replaces require()

agent (sprint-planner)
Why
require(`assets/${avatar}`) is webpack-only and fails under Vite.
Instead of
import.meta.glob (would not work under CRA before V1).
So
A new avatar needs one line in avatar.ts; unknown names fall back to the default.

Never inline SVGs

agent (V1 engineer, in-slice)
Why
Vite inlined small SVGs as data URLs, which broke the unquoted CSS url(...) in Piece.tsx/Promotion.tsx: every piece went blank.
Instead of
Quoting the CSS URLs (would change src/, outside V1's scope).
So
build.assetsInlineLimit returns false for .svg; pinned by tests/build.test.ts.

Package becomes ESM

agent (ci-deploy sprint-planner)
Why
Removes Vite's "ESM syntax in a file loaded as CommonJS" warning, once gh-pages.js is gone.
Instead of
Renaming to vite.config.mts.
So
Any root Node script must be ESM or .cjs.

Checks on every PR, plus a gitleaks job

agent (ci-deploy sprint-planner)
Why
Wave PRs into the plan branch get real Linux CI too; a secret scan before anything is public.
Instead of
Checks only on PRs into main.
So
Only deploy has write permissions; deploys queue and never cancel.
